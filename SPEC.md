# Pinlease first slice

The rules that must not be got wrong are this file.

This slice builds the lease record, borrow, release, status and the home pin. Tests use a local git checkout. Test 12 (a real second machine) is not this slice. The shared server lock is not changed here.

These choices are part of this tool. A missing lease field and JSON null mean free. An empty object or array does not. The command line stores no process id. A missing id is not a lost borrower. A stored id that is dead, or that this process cannot signal, shows UNKNOWN and the lease stays held. A missing borrower or a non-positive duration is refused before any move. An unexpected error after the command has started exits 3 and does not clear a lease whose checkout already moved. A git failure on the read-back after that move is uncertain too. A duration that is not plain ASCII digits is refused before any record. A free host is granted only to the head of the queue, matched by borrower and by the commit id both texts resolve to. `leave` removes a waiter and does not move the checkout. If the recorded home pin cannot be resolved, the holder name stays and no restore intent is written. A named human may pass `--to COMMIT` to restore to a commit that does resolve. A dirty checkout is refused before a restore intent, and the holder name stays. `observed_commit` is printed only when status is run with `--check`. A control character in a borrower, a reason, or a human name is refused before any record. A settings file must name one host. An uncertain borrow names the lease id in the message, including when the last record write fails after the checkout and the read-back have succeeded. Spec test 12 is a written plan on a throwaway local git host, and is not run here.
